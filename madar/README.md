# مدار — Madar

تطبيق ويب (يعمل على الجوال والكمبيوتر ويمكن إضافته للشاشة الرئيسية) لتوزيع مواعيد الحضور المرن:
يختار الموظف فترة وصوله لكل يوم، ويعرف متى ينطلق بناءً على تقدير الرحلة، وتضبط الجهة المرونة وتتابع توزيع الحضور والالتزام.

> هذا تنفيذ للتصميم المقترح. الربط الفعلي مع أنظمة الجهات (الدخول الموحد، الموارد البشرية، الحضور) يحتاج موافقتها وإتاحة أنظمتها.

## البنية

| الجزء | التقنية | المسار |
|---|---|---|
| الواجهة | Next.js 15 (App Router) + React 19، عربية RTL، PWA | `apps/web` |
| الخادم | NestJS 11، مهام خلفية (`@nestjs/schedule`)، تحديد معدل الطلبات | `apps/api` |
| البيانات | PostgreSQL 16 (SQL migrations) | `apps/api/src/db/migrations` |

الواجهة تمرّر `/api/*` إلى الخادم (Next rewrites) لتبقى الجلسة في ملف تعريف ارتباط `httpOnly` على النطاق نفسه.

## التشغيل محليًا (خطوة بخطوة)

1. ثبّت [Node.js](https://nodejs.org) (نسخة LTS) و[Docker Desktop](https://www.docker.com/products/docker-desktop/) وافتح Docker Desktop.
2. حمّل الكود وادخل مجلد مدار:
   ```bash
   git clone -b claude/adoring-hawking-s7mzhi https://github.com/VGaseven/VG-hoster.git
   cd VG-hoster/madar
   ```
3. شغّل قاعدة البيانات: `docker compose up -d db`
4. ثبّت الحزم وأنشئ البيانات التجريبية: `npm run setup`
5. شغّل التطبيق: `npm run dev` (اتركه يعمل)
6. افتح **http://localhost:3100** وادخل بـ `sara@demo.madar.sa` (موظفة) أو `admin@demo.madar.sa` (مسؤول).

المنافذ: الواجهة 3100 والخادم 4100 (بعيدًا عن 3000 الذي تستخدمه برامج أخرى غالبًا). للإيقاف: Ctrl+C.

الاختبارات (تحتاج قاعدة `madar_test`):

```bash
createdb -O madar madar_test
npm test
```

## ما الذي يعمل

**الموظف (`/`)** — ثلاث خطوات: اختر اليوم ← اختر وقت الوصول ← أكّد
- بطاقة «موعدك القادم»: متى تنطلق، وزر «ابدأ الملاحة في خرائط Google» يبدأ من **حي الانطلاق** (وليس الموقع الحالي).
- **موعدي المعتاد**: يحدده الموظف مرة واحدة، ثم «احجزها كلها بضغطة» لحجز الأيام القادمة؛ وإن اكتمل وقته يُختار أقرب وقت متاح تلقائيًا.
- خيار «احجز الوقت نفسه لباقي أيام الأسبوع».
- التغيير يُعتمد **تلقائيًا** متى توفر مكان (افتراضيًا)، والموعد السابق يبقى ساريًا حتى يتم.
- يحدد حي الانطلاق فقط (لا عنوان منزل، ولا تتبع مستمر) ووسيلة التنقل.

**الجهة (`/admin`)**
- **حضور اليوم**: كل موظف ووقت وصوله، ووقت انطلاقه المخطط، وحضوره الفعلي، وحالته (في موعده / متأخر / لم يحجز / إجازة)، مع بحث وتصفية وتصدير Excel، والتنقل بين الأيام.
- **الموظفون**: الموعد المعتاد لكل موظف، ومواعيده القادمة، ونسبة التزامه خلال ٣٠ يومًا.
- **الأوقات والسعة**: الحد الأقصى لكل وقت وصول، وإغلاق وقت عند الحاجة.
- **طلبات التغيير**: فقط إذا فعّلت الجهة المراجعة اليدوية.
- **الإعدادات**: نافذة الحضور، مدة كل وقت، الحدود، أيام العمل، مهلة التغيير، مهلة السماح.
- **استيراد البيانات**: قائمة الموظفين، الإجازات، سجل الحضور (CSV)، مع تقرير أخطاء لكل سطر.

## قرارات التصميم

### الحجز وإغلاق الفترات
- «السعة» حصة لتنظيم حجوزات المشاركين، **وليست سعة الطريق**.
- الحجز زيادة شرطية ذرّية داخل معاملة:
  `UPDATE slots SET booked_count = booked_count + 1 WHERE id=$1 AND booked_count < quota AND NOT closed`
  فلا تُتجاوز الحصة مهما تزامنت الطلبات (اختبار: ١٢ طلبًا متزامنًا على حصة ٣ → ٣ حجوزات بالضبط).
- فهرس فريد جزئي يضمن حجزًا نشطًا واحدًا لكل موظف في اليوم.
- حجز الأسبوع معاملة واحدة بترتيب ثابت للفترات لتفادي الجمود؛ عند فشل يوم يُلغى الكل وتُعاد البدائل.
- اعتماد طلب التغيير يعيد فحص حصة الفترة الجديدة؛ إن امتلأت يبقى الطلب معلّقًا والموعد السابق ساريًا.
- تُرفض: الأيام الماضية، الفترات التي بدأت، ما بعد مدى الحجز، غير أيام العمل، أيام الإجازة، الموظف غير المؤهل.

### Google Maps
- `apps/api/src/routes/google-routes.ts` يستدعي **Routes API** (`computeRoutes`) مع `departureTime` و`TRAFFIC_AWARE`، ويطلب الحقول اللازمة فقط عبر `X-Goog-FieldMask`.
- Routes API يقدّر الرحلة **لوقت انطلاق محدد**، فيجرب `planner.ts` أوقات انطلاق متتالية حتى يتقارب التقدير (٢–٤ طلبات عادة)، ثم يضيف هامش المشي والدخول للمقر.
- التقديرات تُخزن مؤقتًا لفترة قصيرة (`ESTIMATE_CACHE_TTL_MIN`) لتقليل التكلفة ثم تُحذف بمهمة دورية؛ **لا تُؤرشف ولا تُستخدم للتحليل أو التدريب**. لوحة الجهة تعتمد على بيانات مدار والحضور المعتمد فقط.
- عند غياب المفتاح أو تعطل الخدمة (مهلة ٥ ثوانٍ) يُستخدم تقدير احتياطي تقريبي، ويظهر للموظف أنه تقريبي.
- الملاحة عبر Maps URLs (`https://www.google.com/maps/dir/?api=1&destination=…`) — تكامل بين التطبيقين لا يحتاج إضافة داخل Google Maps.
- راجع [سياسات Routes](https://developers.google.com/maps/documentation/routes/policies) لمتطلبات الإسناد والتخزين قبل الإطلاق.

### تسجيل الدخول والصلاحيات
- **OIDC** (Authorization Code + PKCE، تحقق من `id_token` عبر JWKS و`nonce`) — يُضبط بمتغيرات `OIDC_*`، ويُربط الموظف ببريده في جهة `auth_type='oidc'` ذات `oidc_issuer` المطابق.
- **SAML غير مفعّل** في هذه النسخة (يحتاج تهيئة خاصة بكل جهة).
- نفاذ يتحقق من الهوية فقط؛ الوظيفة والمقر والأهلية تأتي من الموارد البشرية للجهة.
- جلسة JWT (HS256، ٨ ساعات) في ملف تعريف ارتباط `httpOnly; SameSite=Lax`، وترويسة `X-Requested-With: madar` إلزامية للطلبات المعدِّلة (CSRF).
- عزل الجهات: كل استعلام إداري مقيّد بـ `org_id` المسؤول. سجل تدقيق (`audit_log`) للحجوزات والتغييرات والسياسات والاستيراد.
- `helmet`، تحديد معدل (120 طلبًا/دقيقة)، تحقق من المدخلات بـ zod.
- الدخول التجريبي بالبريد مخصص للتطوير والعروض، ويُعطّل في الإنتاج.

### التذكيرات
- تُجدول عند الحجز: مساء اليوم السابق (20:00) وقبل الانطلاق.
- مهمة كل دقيقة ترسلها إلى `REMINDER_WEBHOOK_URL` (أو السجل) باستخدام `FOR UPDATE SKIP LOCKED`، فتعمل بأمان مع أكثر من نسخة. تُلغى تذكيرات الحجز الملغى أو المستبدل.

## API الداخلية (مختصر)

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/api/auth/options` · `/api/auth/me` | خيارات الدخول، المستخدم الحالي |
| POST | `/api/auth/dev-login` · `/api/auth/logout` | دخول تجريبي، خروج |
| GET | `/api/auth/oidc/start` · `/api/auth/oidc/callback` | دخول بحساب الجهة |
| GET | `/api/me/slots?from&to` | الفترات المتاحة وسياسة المقر والإجازات |
| GET | `/api/me/slots/:id/plan` | خيارات الانطلاق ورابط الملاحة |
| GET/POST | `/api/me/bookings` | حجوزاتي / حجز يوم أو أسبوع `{items:[{date,slotId}]}` |
| DELETE | `/api/me/bookings/:id` | إلغاء |
| POST | `/api/me/bookings/:id/change` | طلب تغيير `{newSlotId, reason?}` |
| DELETE | `/api/me/changes/:id` | سحب طلب التغيير |
| PUT | `/api/me/district` · `/api/me/travel-mode` | حي الانطلاق، وسيلة التنقل |
| GET | `/api/admin/sites` · `/api/admin/sites/:id/dashboard` | المقار، لوحة التوزيع والالتزام |
| GET/PUT | `/api/admin/sites/:id/policy` | سياسة المرونة |
| GET/PATCH | `/api/admin/sites/:id/slots[/:slotId]` | الفترات وتعديل الحصة/الحد الأدنى/الإغلاق |
| GET/POST | `/api/admin/changes[/:id/decision]` | طلبات التغيير واعتمادها `{approve, note?}` |
| POST | `/api/admin/imports/:kind` | استيراد CSV (`hr` · `leaves` · `attendance`) `{csv}` |
| POST | `/api/admin/integrations/hr/sync` | مزامنة من API الموارد البشرية |
| GET | `/api/health` | الحالة ومصدر التقديرات |

## ما زال مطلوبًا قبل التجربة الميدانية
- موافقة جهة تجريبية وتحديد طريقة ربط الدخول والموارد البشرية والحضور فعليًا.
- مفتاح Google Maps مقيّد بالخادم ومراجعة الترخيص والإسناد وحدود التكلفة.
- ربط قناة التذكيرات (بريد/SMS/إشعارات) عبر الـWebhook.
- قياس ميداني: توزيع الحضور، زمن الرحلات، الالتزام — الأرقام الافتراضية في الإعدادات (هامش الدخول، الحصص، سرعات التقدير الاحتياطي) افتراضات وليست نتائج.
